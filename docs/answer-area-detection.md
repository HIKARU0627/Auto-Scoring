# 回答欄の検出（Issue #105）

生徒の答案そのものから回答欄の矩形を見つけ、人がその場で直して確定する経路。
`complete-registration` がプロファイル確定を必須にしているため、**これが無いと
どのテストも `ready` にならず、答案の処理が始まらない**。

関連: [test-registration.md](./test-registration.md)（`ready` になる条件）、
[answer-intake-and-preprocessing.md](./answer-intake-and-preprocessing.md)（確定した
回答欄で答案を crop する側）、簡易設計書 §26.1.1（送信の分離）。

## 1. なぜ答案から検出するのか

- **模範解答 PDF は存在しない**（#95 決定 1）。回答欄が印字されているのは
  答案用紙そのものだけである。
- 計測した**生徒答案 PDF 11 件はすべてテキスト層 0 文字**（紙のスキャン）。
  したがって**入力はページ画像だけ**で、「テキストを試して駄目なら画像」という
  分岐は書いていない。分岐する余地が無い。

## 2. 経路

| メソッド | パス                               | 役割                                                                              |
| -------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| `GET`    | `/tests/{id}/answer-layout`        | 参照答案の有無（ページ数、未取込なら `null`）と、この端末で自動検出が使えるか     |
| `PUT`    | `/tests/{id}/answer-layout`        | 回答欄を決める答案を 1 枚保存する（テストにつき 1 枚。差し替え可）                |
| `GET`    | `/tests/{id}/answer-layout/pdf`    | 画面のオーバーレイが上に描くための PDF バイト列                                   |
| `POST`   | `/tests/{id}/answer-layout/detect` | 全ページを provider に送り、DRAFT プロファイルの `ANSWER_AREA` 領域として保存する |

編集と確定は**既存の経路をそのまま使う**: `PUT /tests/{id}/profile` と
`POST /tests/{id}/profile/confirm`。検出結果は `domain.profile.Profile` の
領域そのものであって、別の保存物ではない。新しいテーブルも、新しい JSON ストアも、
マイグレーションも増やしていない。

保存と検出を分けてあるのは、**provider 呼び出しが失敗したときに答案を選び直さずに
押し直せる**ようにするため。検出は 1 回の長いマルチモーダル呼び出しで、失敗は普通に起きる。

### 答案の取り込みが、プロファイルの始まりでもある

模範解答 PDF の無いテストには**プロファイルが存在しない**。プロファイルが無いと
領域を置く**ページ様式が無い**ので、「領域を手動追加」も押せない —— つまり
**最初の一手が踏めなかった**（レビュー 1 回目 P1）。

答案の取り込みは「この座標はどの文書のものか」を宣言する行為そのものなので、
`PUT /answer-layout` が**空の DRAFT プロファイルを作る**。これで自動検出を 1 度も
呼ばずに、手で回答欄を引いて確定するところまで行ける。

### 参照答案とプロファイルは一緒に動く

領域は**その答案の上の座標**なので、答案を差し替えると全領域の意味が変わる。
したがって `PUT /answer-layout` は `/detect` や `PUT /profile` と**同じ per-test ロック**
を取り、**`revision` を上げ**（古い答案を見て確認した revision に紐づく確定は
stale として弾かれる）、**確定済みプロファイルの答案差し替えは 409 で拒否**する。
これが無いと、別クライアントがレビュー中に答案を差し替えられ、確定済みテストの
参照答案さえ変更できた（レビュー 1 回目 P2）。

新しい答案に無いページの領域は解釈しようが無いので外れるが、**件数を返す**
（`dropped_region_count`）。黙って消さない。

### 参照答案は submission ではない

`Submission` 行を作らないし、採点もされない。**`draft` のテストにも取り込める**必要が
あるからである（`intake_submission` は `ready` でないテストを拒否し、テストは回答欄が
確定するまで `ready` にならない）。置き場所は `app-data/tests/<id>/answer-layout.pdf`。

## 3. 送信は目的で分ける

|          | 何を送るか                     | いつ                                         |
| -------- | ------------------------------ | -------------------------------------------- |
| **検出** | 答案の**全ページ画像**         | **テスト 1 件につき 1 回**（押したときだけ） |
| **採点** | **切り出した回答欄の画像**だけ | 答案ごと・設問ごとに毎回                     |

この非対称性が、識別情報の露出を最小にする根拠である（簡易設計書 §26.1.1、#95 決定 7）。

**書けないこと**: 検出のときは**ページに印字・手書きされているものがそのまま渡る**。
講師名・塾名・日付・QR コード、そして生徒が氏名を書いていればそれも渡る。
**手書きの氏名を確実に消す手段は無い。** 画面にもそう書いてある
（`test_settings_page_test.dart` が固定している）。

## 4. 設問との対応は選択問題として問う

候補は**そのテストの確定済み設問番号**（`Question` 行。#103 以降は
`/criteria/confirm` が確定済み配点表から作る行そのもの）に、
「どれか分からない」を表す番人値 `__unassigned__` を足したもの。
ワイヤ上の JSON Schema でも `enum` として強制し、**候補外の値は `SchemaViolation`**
（#101 が答案の帰属で確立した規律）。

設問が 0 件のときは検出を**実行しない**（409）。選択肢の無い選択問題は選択問題ではなく、
自由回答にすると存在しない配点に矩形が結びつく。

### 値の制約はワイヤから外し、ローカルで検査する

Vertex AI は `responseJsonSchema` を復号制約にコンパイルし、数値の min/max や
文字数上限で大きくなりすぎると `400 INVALID_ARGUMENT` を返す（#103 が実測）。
そこで **min/max・maxLength 等はワイヤ上のスキーマから落とし、`enum` だけ残す**。
値の検査は `domain.answer_area_detection.parse_answer_area_detection` が
ローカルで必ず行う。再び足して壊さないよう、制約キーワードが混ざったら落ちるテストを置いた。

## 5. 黙って落とさないための 3 つの状態

| 状態           | 何が起きたか                               | 確定を止めるか    |
| -------------- | ------------------------------------------ | ----------------- |
| **未検出**     | 答案に回答欄があるはずだが見つからなかった | **止めない**      |
| **答案に無い** | この答案には回答欄が無いと AI が報告した   | **止めない**      |
| **設問未割当** | AI が枠を見つけたが設問を決められなかった  | **止める**（422） |

### 「未検出」と「答案に無い」を分ける（#164）

**この 2 つは講師のやることが逆である。**未検出なら枠を引く。答案に無いなら、
採点基準か登録した答案のほうを直す。片方しか無かったとき、**存在しない枠を探させる**
案内が出ていた。

分けられるのは AI に聞いているからで、**導出はできない**。矩形が無いという事実は
両者で同じ形をしている。したがって
`AnswerAreaDetectionOutput.questions_not_on_these_pages` を
`Profile.absent_question_numbers` に**保存する**。ここだけが「毎回導出する」原則の例外で、
理由は導出元が存在しないことである。

**保存するのは番号だけで、判定は毎回やり直す**
（`domain.answer_area_detection.missing_question_numbers`）。講師が「答案に無い」と
言われた設問に自分で枠を引いたら、その瞬間に両方のリストから消える。
保存した主張を書き戻す必要は無い。

**両方に入った設問は `ValidationError`。片方にも入らない設問はエラーにしない** ——
1 問の申告漏れのために、見つかった枠を全部捨てるほうが高くつく。申告漏れは
「未検出」（保守的なほう）として扱う。

どちらも保存しない。**確定済み設問の集合と `ANSWER_AREA` の label 集合から毎回導出する**。
保存すると「人が矩形を引いた直後」——まさにその表示が意味を持つ瞬間——に陳腐化する。

### なぜ配点の「不明」と扱いが違うのか

**静かに間違うものは止め、うるさく未解決になるものは通す。**

- **配点の不明はブロックする**（#103）。不明のまま確定すると
  **静かに誤った `Question.points`** になり、その設問の採点結果が丸ごとずれる。
  誰も気づかない。
- **回答欄の未検出はブロックしない。** 未検出のまま進むと
  `adapters.submission_intake._build_answer_image` が**ページ全体を送り**、
  `no_answer_area_defined` として `NEEDS_REVIEW` に落とす。
  **添削レビュー画面で人の目に触れる。** 大きな声で未解決になる。

止めるほうを選ぶと、後述のページまたぎ設問を持つテストが詰む。

**設問未割当を止める理由**は別で、`build_questions_and_rubrics` は
どの設問にも一致しない label の領域を**例外を出さずに無視する**。
そのまま通すと「AI が枠を見つけ、誰も割り当てず、何も言わずに消えた」になる。

## 6. 実資料を計測して分かったこと

内容は載せない。数値と構造のみ。

```
生徒答案 PDF        : 11 件（11 教科、各 1 ファイル）
テキスト層          : 全件 0 文字
表示ページサイズ    : 全件 595 x 842 pt（A4 縦）で完全に同一
ページ数            : 1 ページ x 10 教科、3 ページ x 1 教科
/Rotate             : 0 が 7 件、270 が 3 件、90 が 1 件
```

### `FormatSignature` は教科を区別できない

11 教科すべて同寸なので、`domain.profile.FormatSignature`（ページ数＋ページ寸法）で
判別できるのは**ページ数の違いだけ**である。

そして**様式違いの混入検知は既にあった**。`domain.submission_intake.describe_coverage_issue`
が、答案のページ数と確定済み設問が参照するページを突き合わせ、`missing_pages` /
`extra_pages` を `NEEDS_REVIEW` に落としている。本 Issue は同じものを作らず、
その経路が効くことをテストで固定しただけである
（`tests/test_answer_area_registration_flow.py`）。

**書けないこと**: これで検知できるのは**ページ数と紙サイズの違いだけ**である。
**同じ A4 縦で中のレイアウトだけ違う答案は検知できない。**

### 1 設問 = 1 矩形が成り立たない例が 2 種類ある

0. **`__unassigned__` は「同じ設問」ではない。** モデルが帰属を決められなかった枠は、
   **1 つずつ別の領域として残す**。まとめると、モデルが「決められない」と言ったことを
   決めたことにしてしまい、別設問の解答や間の領域を巻き込み、しかも**元に戻せない**
   （まとめた 1 個をあとで 1 設問に割り当てても、どの部分が誰のものだったかは復元
   できない）。`answer_regions[0]` の「残りを捨てる」を「残りを混ぜる」に置き換えても、
   失われる情報は同じである（レビュー 1 回目 P1）。
1. **1 設問の解答欄が同一ページ上の複数の枠**（ある教科は 1 設問に小枠 5 個）。
   `Question.answer_area` は矩形 1 つなので、**同じ設問番号・同じページの枠は
   union して 1 つにまとめ**、「N 個の枠を 1 つにまとめました」を注記として画面に出す。
   併せて `build_questions_and_rubrics` の既存バグ（`answer_regions[0]` しか見ず
   残りを黙って捨てていた）を直した。
2. **1 設問の解答欄が 2 ページにまたがる**（ある教科は「（その1）」「（その2）」）。
   ページをまたぐ union は意味を持たない（座標空間が違う）ので**まとめない**。
   両方の領域を残し、確定時に `CrossPageRegionError` が
   「この設問の領域が複数ページにある」と言う。
   **`Question` は `page: int` と矩形 1 つしか持てないので、本アプリはこの設問を
   今は表現できない。** 直すには `Question` のスキーマ変更・migration・crop /
   annotation / export / レビュー画面まで波及するため、別 Issue とする。

### 得点記入枠（範囲外）

ある教科の答案には設問ごとに `／6点` の得点記入枠が印字されている。
`Question.score_area`（採点結果の書き込み位置）そのものだが、#103 が
「配点の入力口を 1 つに絞る」ために `SCORE` 領域を画面から作れなくしたばかりなので、
本 Issue では触らない。観察として記録するにとどめる。

### 設問数と検出率の関係は見せかけだった（#164）

`live-run-report-5.md` は「設問 3 問以下は検出率 100%、5 問以上は 27%」を 3 回再現した。
**測ったら、分母が違っていた。**

登録されている答案 PDF は、**複数ページある解答用紙の 1 ページだけ**である
（フッタ印字で確認: 1/9、1/2、2/4、2/5、1/5、6/7、1/11、1/2）。一方 `採点基準.pdf` は
1〜8 ページあり、課題全体の設問を並べる。**採点基準の抜粋範囲と答案の抜粋範囲が
一致する教科だけが 100% になっていた。**設問数との相関は、範囲の広い採点基準ほど
設問が多くなるという副作用にすぎない。

紙の上に回答欄が実在する設問だけを分母にすると（画像を見て人が数えた）:

```
設問が5問以上の5教科
紙に回答欄が実在する設問  : 11
紙に実在する枠           : 22
うち正しい設問に帰属できた: 7  (#164 着手前, 実機再検証 #5)
```

**モデルは空で返していない。パーサも検証も 1 件も落としていない。**
本番と同一のペイロードを再送して測った結果（`finishReason` は全件 `STOP`、出力トークンは
上限 65535 に対し 208〜582）:

```
物理   設問5  返ってきた枠 4
現代文 設問5  返ってきた枠 6
地理   設問6  返ってきた枠 2
生物   設問11 返ってきた枠 5
古漢   設問10 返ってきた枠 5
```

### 実資料に対して検出を実行した結果

11 教科すべてに Vertex AI Gemini で検出を実行した（ローカル、リポジトリ外）。

```
subjects                    : 11
crashed                     : 0
schema violations           : 0
provider unavailable        : 0
answer areas produced (sum) : 22
subjects producing >=1 area : 11
unassigned areas (sum)      : 0
seconds per subject         : 3-14
```

**この数字は精度ではない。** 確かめたのは
**落ちないこと**と**読めなかった箇所が分かること**だけである。

- **候補集合は本物の配点表ではない。** #103 が未マージなので、汎用の設問番号リストを
  与えた。したがって帰属の正しさは測っていない。
- **「未割当 0 件」は良い結果を意味しない。** モデルが毎回どれかの候補を選んだ、
  というだけである。**したがって未割当の経路は実資料では 1 度も通っていない**
  （固定しているのは合成 fixture のテストだけ）。
- **同じテストの別の生徒の答案が 1 枚も無い。** 確定した回答欄を他の答案に
  使い回したときの精度は、現有データでは測れない。

4 教科分の検出結果を答案の上に重ねて目視もした（リポジトリ外）。**測定ではない**が、
記録しておく価値のある傾向があった:

- 横書きの答案では、回答欄のおおよその位置に矩形が出るが、**上端・下端が食い込む**。
  人が端を引き直す前提の品質である。
- **縦書き・右から左に読む教科では明確に悪い。** 矩形が解答欄の列から横にずれ、
  1 つの設問がまるごと検出されなかった。

**だからこそ、AI の提案をそのまま使わない。** 検出結果は必ず答案の上に重ねて表示し、
人がその場で直してから確定する。

## 7. 画面

テスト設定画面の「テストプロファイル（回答欄の位置）」節。
`features/test_registration/answer_area_editor.dart`。

- 答案のページを `pdfrx` で描き、その上に矩形を重ねる
  （`pdf_review_page.dart` と同じ `pageOverlaysBuilder` +
  `core/pdf_review_geometry.dart` の `normalizedRectToLocal`。新しい描画基盤は作っていない）
- ドラッグで新規作成、選択して移動・リサイズ、削除
- 設問はドロップダウン（**選択問題**。自由入力の欄は無い）
- **未検出の設問**をチップで一覧。押すと「次に引く設問」に入る
- **設問未割当**は強調色（`AppStatusTone.attention`）で、一覧の先頭に置き、
  残っているあいだ確定ボタンを無効にして理由を書く
- 色だけに頼らない（枠線の太さ・ラベル文字・アイコンで同じ区別がつく）
- 数値での編集（既存の領域ダイアログ）を各行から開ける。
  **ポインタ無しでも矩形を置ける**ようにするため

### 見ていないものを確定させない

**答案を画面に表示できていない間は、回答欄を含むプロファイルを確定できない。**
回答欄の確定は「この座標がこのページのここにある」と人が保証する行為なので、
白紙の枠の上でそれをするのは、誰も見ていないものを確定することにほかならない。
答案の取得に失敗したら**握りつぶさずに表示して再試行させる**（Issue #85 が
5 ラウンドかけて確立した規律。レビュー 1 回目 P1）。

### 画面の判定は、編集後の状態から毎回計算する

**未検出件数・未割当件数・答案を見たかどうかは、すべて編集中の作業コピーから
毎回計算する。** 最後のサーバー応答を持ち回ると、人が枠を引いた・消した・割り当て
直した瞬間に古くなる —— そしてその瞬間こそ、その表示が読まれる瞬間である
（レビュー 2 回目）。同じ形が依存関係グラフの「並列実行可能な層」（Issue #16 で
修正済み）と「要確認の設問」（レビュー 2 回目で修正）にもあった。

確定を止める理由は**確定ボタンの真横**に出す。スクロールして戻らないと読めない
理由は、押す前に読まれない。

### 検出のやり直しは、何を失うかを先に言う

検出は**手で引いた回答欄も含めて**すべての回答欄を置き換える（サイドカーは両者を
区別できない）。置き換える件数を先に示して確認を取る —— 黙って捨てるのは、
帰属できない枠をまとめるのと同じ失敗（結果は正しく見え、元は消えている）。

### 費用は「知らないことを知らないと言う」

呼び出し回数とページ数は正確に出す。**金額は単価を設定していないので出さない。**
`0 円` と書くのは、このアプリが根拠を持たない数字である（PR #104・#107 と同じ規律）。
押し直すたびに同じだけ呼ぶことも書く。

**手動追加（`_addRegion`）は残してある。** 手で引いた矩形と検出された矩形は同じもので、
同じ画面で同じように編集する（受入条件 6）。自動検出が使えない端末でも、
答案が無くても、回答欄は引ける。

## 7.5. 座標はモデルに推定させない（Issue #122）

Issue #105 の時点では、枠の座標はモデルの回答をそのまま保存していた。実機検証で
0 点になった 15 設問のうち 9 件がこの枠のずれで、**AI には余白が渡っていた**。
Issue #122 が原因を実測した。

### 分かったこと — 変換は無実、モデルが測っていない

**座標変換にバグは無い。** 既知位置の矩形を `/Rotate` 0/90/180/270 でレンダリング
して測ると、`domain.pdf_geometry` の期待値との誤差は**小数第 4 位まで 0.0000**。
同じラスタからの `crop_normalized_rect` は**インク比率 1.0000**。検出と切り出しは
同じ関数・同じ scale・同じ正規化空間を共有し、間に変換が 1 つも無い
（`tests/test_answer_area_coordinates.py` が固定している）。

**モデルは列を測っていない。** 列の座標を厳密に決めた合成用紙で対照実験した。

| 対照                                 | 紙の上の列                        | 返ってきた枠                                                       |
| ------------------------------------ | --------------------------------- | ------------------------------------------------------------------ |
| A（列がほぼ等間隔）                  | 0.3493 / 0.5239 / 0.6658 / 0.8086 | 中心誤差 −0.018 〜 +0.006、幅は 4 本とも一律 0.10                  |
| B（間隔を 0.220 / 0.160 / 0.300 に） | 0.1998 / 0.4198 / 0.5793 / 0.8799 | 0.3748 / 0.5320 / 0.6892 / 0.8464 = **差がすべて 0.1572 の等間隔** |

紙が等間隔でないのに、返る枠は等間隔になる。**本数と読み順は正しく、位置だけが
創作**である。幅も定数で、別文書・別実行で 0.0605 が繰り返し出る（紙の上の真の
列幅は 0.0487 と 0.0457 でばらついている）。最大誤差はページ幅の **0.181**。

**したがって定数オフセット補正は誤りである。** Issue #122 は当初「一貫して右へ
3〜4%」と記録されたが、対照 A では左にもずれ、誤差 0.006 に収まることもある。
固定量を引く補正は、いま合っているケースを壊すだけになる。
`tests/test_answer_area_snapping.py` の 2 本が、その補正が入ると落ちる。

### どうしたか — 罫線を測って渡し、返りを同じ罫線に合わせる

印刷罫線は測れる。`adapters.image.ink.measure_page_ruling` が、切り出しと同じ
ラスタからモルフォロジだけで拾う（新規依存なし。既存の `opencv-python`）。

1. **測った罫線をプロンプトに渡す**（`_prompt` 規則 10、`ANSWER_AREA_PROMPT_VERSION`
   は `v2`）。座標を、設問番号と同じ**選択問題**にする。
2. **返ってきた枠を同じ罫線にスナップする**（`domain.answer_area_snapping`、
   `regions_from_detection` から。マージ**前**に掛ける）。

同じことを、読める場所と強制できる場所の両方で言う——`_prompt` が設問番号の enum に
対して既に採っている型である。

実資料での効果（内容は載せない。座標と比率のみ）:

|                          | 従来                   | 罫線を渡した後                 |
| ------------------------ | ---------------------- | ------------------------------ |
| 縦書き教科 1             | 検出 0 件（2 回とも）  | 真の解答列 3 本に正確に着地    |
| 同、切り出しのインク比率 | 0.034 / 0.063          | 0.078 / 0.098 / 0.118          |
| 合成対照 B               | 4 枠すべて創作・等間隔 | 返る値が**全て実在の罫線の値** |

スナップ許容量 `SNAP_TOLERANCE = 0.015` は実測で決めた。3 教科 52 辺の
「辺 → 最寄り罫線」距離に **[0.015, 0.020) が n=0 の裂け目**がある。
ただし 52 辺・3 教科は多くない。**テストが固定しているのは性質**（近い外しは
吸着し、創作は動かさない）であって、この数値ではない。

### 直っていないこと — スナップは創作を救えない

**モデルが位置を創作した枠は、どんな後処理でも救えない。** 隣の列の近くに落ちた枠は、
隣の列に**自信を持って吸着する**。`test_a_box_over_the_wrong_column_snaps_onto_the_wrong_column`
が、これを既知の性質として固定している。

だから Issue #122 の後半——切り出しがほぼ余白なら採点前に止め
（`domain.submission_intake.is_nearly_blank_crop`）、**AI が見た画像を採点画面に出す**
（`features/pdf_review/answer_crop_view.dart`）——は、この修正の飾りではなく、
**この修正が原理的に届かない範囲を埋める唯一の手段**である。

より強い規則（枠を最寄りの「罫線で囲まれたセル」ごと移す）も実装して測ったが、
10 例中 2 例で**悪化**し、余白の枠を巨大化させて空白判定を隠したため**採用しなかった**。

## 7.6. 検出する紙と切り出す紙のずれ（Issue #130）

検出は参照答案 PDF に対して行い、罫線もその画像から測る。切り出しは**別の生徒の**答案 PDF
に確定した正規化座標をそのまま当てる。**別々にスキャンされた 2 枚の紙**なので、印刷罫線の
位置は一致しない。Issue #130 でその差を実測した。

**実測**（同一様式 9 まとまり・23 文書・30 ページ対、うち数値が出た 30 軸。詳細と再現
コマンドは [`poc-5-scan-to-scan-drift.md`](./poc-5-scan-to-scan-drift.md)）:

| 原因                 | 横方向（ページ幅）の最大    | 縦方向（ページ高）の最大    |
| -------------------- | --------------------------- | --------------------------- |
| 回転（最大 0.94 度） | 0.0116                      | 0.0058                      |
| 平行移動             | 0.0088                      | 0.0266                      |
| 伸縮                 | 0.0035                      | 0.0027                      |
| **合成した実移動量** | **0.0154**（中央値 0.0074） | **0.0337**（中央値 0.0153） |

**回答欄の幅 0.048 に対して、横方向の最大 0.0154 は列幅の 32%。半幅 0.024 より小さい。**
切り出しの中心は列の中に留まる——**このずれ単独では列から外れない**。Issue #122 が実測した
モデルの創作（最大 0.181）の 1/12 であり、優先順位は変わらない。

### 位置合わせを入れなかった理由

小さいからではない。**位置合わせを駆動する罫線の対応づけが、実資料の 60 軸中 30 軸で
数値にならなかった**——19 軸はそもそも当てはまらず、10 軸は**両立しない 2 通りに読めた**
（「左へ 0.04 動いた」とも「右へ 3% 伸びた」とも読めるページが実在する）。当てはまらない
紙に変換を当てると**ページ上の全部の枠が同時に動く**。§7.5 の受け皿——空白切り出しの tripwire と
採点画面の切り出し表示——は**1 枠の失敗を人に見せる**ためのもので、全枠が揃ってずれた画面は
「そういう様式」に見えてしまう。**測れない紙に当てるくらいなら、当てない。**

### 後から触る人へ

- **「ずれない」とは書いていない。** 0.0074〜0.0154 は、`SNAP_TOLERANCE = 0.015` と同じ桁。
  **スナップを切り出し側にも広げるなら、許容幅を先に見直すこと**——検出した紙で罫線に
  乗せた枠が、切り出す紙では同じ罫線から 0.0154 離れうる。
- **定数補正を足さないこと。** ずれの向きは紙ごとに違う（§7.5 と同じ理由）。
- 将来やるなら**傾き補正から**。横方向の最大 0.0154 のうち 0.0116 が回転由来で、しかも
  角度は罫線の対応づけを要さず**全ページで測れた**。

## 8. 座標は推定させず、測った枠から選ばせる（#164）

#122 は「モデルは測っていない、紋切り型を返す」を実測し、**印刷された罫線**を渡して
その値を写させた。#164 は同じ方法を 5 教科で測り直し、罫線では届かない失敗が
2 種類あることを確かめた。

1. **辺が短い枠は罫線として検出されない。**ある教科は 0.046 幅の列に小問 a〜e の枠を
   5 個積む。どの辺もページの 10% に届かないので罫線リストに載らず、モデルは結局
   推定する —— 返ってきた 5 個は **ちょうど 0.047 間隔**、#122 が x で見つけた紋切り型と
   同じ署名だった。
2. **罫線リストが完全でも、どの 2 本が枠を囲むかは数字の列からは分からない。**
   ある教科では選ばれた組が**2 つの解答列の間の白紙**を囲んでいた。その切り出しは
   0 点で採点され、人が承認した。

**枠は閉じた輪郭なので、辺から組み立てずに直接測れる**
（`adapters.image.ink.measure_page_boxes`）。これで「矩形を推定する」が、設問番号が
すでにそうであるのと同じ**選択問題**になる。

- 他の枠を含む枠（ページ外枠、ヘッダ枠）は候補にしない。「ページ全体」を答えられてしまう。
- 接している枠は 1 つにまとめる。原稿用紙の 90 マスは「書く場所」1 つであって 90 個ではない。
- 罫線で囲まれていない解答欄（「考え方・計算過程」の余白）は候補が作れないので、
  `DetectedAnswerAreaOutput.bbox` で矩形を書く道を残してある。そこだけは #122 の
  snap がそのまま効く。

### 枠を測ったページには罫線リストを渡さない

**実測して決めた。**両方を並べて渡すと、モデルは数字から矩形を組み立てるほうへ戻る ——
ある教科では、直前に渡された候補リストに枠があるのに、ページの白紙側半分を覆う矩形を
返した。罫線を伏せた 3 回の実行では、同じ教科の枠が毎回そのまま印刷された枠に載った。

罫線は**枠が 1 つも測れなかったページ**のためのもので、モデルが自分で書いた矩形は
どちらにせよ後段で罫線に snap される（`regions_from_detection`）。

### 実測（設問が5問以上の5教科、同一設定で3回）

```
                       着手前   #164 後
正しい設問に帰属      7 / 11    8 / 11
採点に使える切り出し  4 / 11    8 / 11
「答案に無い」の正答  ---      26 / 27
```

### 「答案に無い」は断定しない（#167）

上の表の「『答案に無い』の正答 26 / 27」は、**2026-09-10 に実機再検証 #5 の app-data に対して
測った値**である（設問が 5 問以上の 5 教科、`gemini-2.5-flash`、同一設定で 3 回、いずれも同結果）。
教材が変われば変わる値なので、**画面には書かない。**画面は 2 つの行動を可能性の高い順に並べる
ことでしか、確からしさを表現しない。数字は古くなったときに誰も気づかないからである。

誤報告 1 件（ある教科の 1 設問）は、紙に回答欄があるのに「答案に無い」と報告する。
向きが逆なので害が大きい —— 講師は指示どおり採点基準を見に行き、そこには何も無い。
そこで文言を「回答欄が**無いと判定された**」から「回答欄を**見つけられなかった**」に変え、
**手で枠を引く経路をチップの直前に置いた**（末尾の一文だと読み飛ばされる）。
これが「自動でどうしても取れなかったものだけ人が直す」を実際に機能させる唯一の経路である。

#### 枠ベースの検算は成立しない（測定済み・再挑戦しないこと）

「未使用の候補枠が残っているなら、そのページの『答案に無い』を信用しない」を 3 変種で評価した。

| 変種                               | 誤報告を直せた | 正しい判定を壊した |
| ---------------------------------- | -------------: | -----------------: |
| 未使用の候補枠が 1 つでもある      |              1 |                 26 |
| 解答枠の内側にあるものだけ         |              1 |                 11 |
| 内側かつ実在の最小回答欄以上の面積 |              0 |                  0 |

未使用の候補枠は全教科に必ず残るが、正体はヘッダ枠・QR の位置検出パターン・大問番号の四角・
得点欄であって回答欄ではない。そして**誤報告の対象になった枠は候補に入っていない** ——
スキャン上で上辺 61%・下辺 79% しかインクが無く輪郭が閉じないためである。したがって
本物らしい枠に絞ると何も発火せず、発火するまで緩めると誤報告の無い教科でも発火する。

枠測定側の修復も 5 通り測ったが、この 1 件を拾える設定はどれも他の 4 教科を壊した
（全方向の閉処理は 21px 必要で別教科の候補が 16→52、線方向の修復は開処理の前後どちらでも
不可か 13px で 16→57、インク閾値 240 はほぼ白い紙をインク扱い、Otsu は偽候補 +17）。

**OCR 無しでの上限がここである。**印字された設問ラベルの位置が取れれば
「その設問のラベルがこのページに在るなら、このページに無いとは言えない」が成り立つが、
それは検出の経路にもう 1 社を足す判断（§3 の非対称が露出最小化の根拠として書かれている）に
なるので、本Issueでは決めていない。

### 設問の並びと回答欄の並びが食い違うことを検査する（#171）

残っている失敗のうち、**縦書き用紙でラベルが入れ替わる**ものは、他と性質が違う。
枠は 2 つとも印刷された列にぴったり載る —— **幾何は正しく、対応だけが逆**である。
その結果、どの設問も未検出にならないので画面は「全設問に回答欄があります」と言い、
2 問は互いの解答で採点される。実機再検証 #5 では 0/10 と 0/20 が確信度高で出て、
人が承認していた。**静かに間違う型**である。

**印字ラベルを読まずに検出できる。** 設問番号には順序があり、紙の上の並びにも順序が
ある（縦書きなら右から左、横書きなら上から下）。入れ替わっていれば順序も逆転する。

登録済みの答案 8 枚すべてについて、正解配置（画像に重ねて目視で確定）を測った
（2026-09-10）:

```
正解配置が読み順で一意に並ぶ  : 8 / 8 教科
読み順が設問順と一致          : 8 / 8 教科
いまの出力に検査をかけたとき  : 旗が立つ 1 教科（実際に入れ替わっている教科のみ）
                                誤検出 0 件 / 見逃し 0 件
```

書字方向も回答欄の形から決まる。縦横比（h/w）の中央値:

```
横書き 6 教科 : 0.18  0.21  0.23  0.24  0.35  0.46
縦書き 2 教科 : 5.76  8.91
```

#### 旗を立てるだけで、直さない

どちらの枠が動いたのかは**幾何からは決まらない**。読み順で貼り直すのは 8 枚の
経験則で正しい結果を書き換えることであり、#122 の「一貫して右へ +0.035」と同じ誤りになる。
画面は組を名指しし、**入れ替えるボタンを 1 つ置く**（矩形は動かさず、ラベルだけ交換する。
保存するまで確定しないので、もう一度押せば元に戻る）。

#### 確定は止めない

`設問未割当` は事実（その枠はどの設問にも属さず、黙って消える）なので止める。
こちらは **8 枚から測った経験則**であり、誤検出が出たときに正しいプロファイルを
確定できなくしてはいけない。**静かに間違うものは止める**という原則には反するが、
その原則が守ろうとしているもの（誰も気づかないこと）は、名指し＋1 クリックの修正で
達成できる。

#### 成り立たない条件

- **縦書きの標本は 2 教科しかない。**0.46 と 5.76 の間は空いているが n=2 である。
  縦書きで横長の解答欄が来れば書字方向の判定が崩れる
- **1 ページに 1 問しか無いと検査できない**（8 教科中 1 教科が該当）
- **「採点基準に並んだ設問順 = 紙の読み順」を仮定している。**8 枚すべてで成り立ったが、
  1 教科に 2 セクションある科目（古文＋漢文）で、同じページに両セクションの設問が
  載る紙があれば崩れる。今回の登録ページには起きていない
- **同じ行に左右 2 問**という配置は 8 枚に無く、未検証である

**残っている失敗を書いておく。**

- **現代文は決定的に入れ替わる。**縦書き右→左の用紙で、問一の列と問二の列を取り違える。
  3 回とも同じ結果で、着手前も 0/2 だったので悪化ではないが直ってもいない。
  印字された「問一」「問二」を隣の列に結び付けている。
- **生物の問5 は「答案に無い」と誤報告される。**紙には回答欄がある。
  3 回とも同じ。誤報告はこの 1 件だけで、26 件は正しい。
- **古漢は採点基準側の重複番号を直さないと直らない。**`criteria_extraction._unique_number`
  が付ける `問一 (2)` は人が直すためのプレースホルダだが、直さないまま確定でき、
  そのまま検出の enum に渡る。モデルは「(2)」を小問番号②と読む
  （`note` にそう書いてくる）。正しい番号に直せば問一が①②③、問二が(A)(B)に載る。
