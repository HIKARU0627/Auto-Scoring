# Change Summary 出力形式

`change-explainer` がPRコメントとして投稿する本文の構成・粒度・文体を定める。

## 全体構成

コメント本文は次の順で構成する。冒頭の識別マーカー2行は必須。

```markdown
<!-- change-explainer -->
<!-- change-explainer-head: <HEAD_SHA> -->

# Change Summary

## 変更概要

## 主な変更

## ファイルごとの変更

## 影響範囲

## 注意点

## 用語
```

- H1 は `# Change Summary` の1つだけ。各セクションは H2。
- 内容が無いセクションは省略せず「特になし」と書く（レビュー担当者が「書き忘れ」と区別できるようにする）。ただし `用語` は不要なら省略してよい。
- 日本語で書く。コマンド名・識別子・パスは原文のまま。

## 変更概要

PR全体として何を実装・修正したのかを2〜4文で説明する。何を**変えていないか**も一言添える。

```markdown
## 変更概要

Googleアカウントを利用したログイン機能を追加しました。
既存のメール・パスワード認証フローには変更していません。
```

## 主な変更

PRの要点を箇条書きで5〜8項目程度。粒度は「レビュー担当者が読む順序を決められる」レベル。

```markdown
## 主な変更

- Google OAuth認証処理を追加
- OAuth callback endpoint を追加
- ユーザー情報の保存処理を追加
- OAuth関連テストを追加
```

## ファイルごとの変更

変更の中心となるファイルについて、`なぜ / 何を / 他の変更とどう関係するか` を説明する。

```markdown
### `src/auth/oauth.ts`

Google OAuthの認証処理を追加しました。主に次を担当します。

- Googleへの認証リクエスト
- OAuth callback の処理
- Access Token の取得
- Googleユーザー情報の取得
```

含めない / 簡潔にとどめるもの:

- lockファイル（`pnpm-lock.yaml` / `package-lock.json` など）→ 「依存追加に伴う更新」の一言
- 自動生成ファイル → 生成元と再生成方法のみ
- フォーマットのみの変更 → 「フォーマットのみ」とまとめる
- 単純なリネーム・移動 → 1行で

## 影響範囲

この変更が影響する機能・画面・データ・外部連携を挙げる。後方互換性への影響、マイグレーションの要否も書く。

```markdown
## 影響範囲

認証機能に影響します。既存のメール・パスワード認証には変更ありません。
DBスキーマ変更・マイグレーションはありません。
```

## 注意点

レビュー時・マージ後に注意すべき点、未解決の懸念、レビューで重点的に見てほしい箇所を挙げる。

```markdown
## 注意点

- Google OAuth用の環境変数（`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`）が必要です。
- callback URL の許可リスト登録が別途必要です。
- トークンの保存先は要レビュー（現状はcookie）。
```

## 用語

今回の変更を理解するうえで必要な専門用語のみ、2〜3文で注釈する。一般的な開発用語（API, commit, branch など）は説明しない。

```markdown
## 用語

### OAuth

Googleなどの外部サービスを利用してユーザー認証を行う仕組み。

### Access Token

認証後にAPIへアクセスするために利用する認証情報。
```

## 文体・分量の指針

- レビュー担当者が「概要 → 影響範囲 → どのdiffを読むか判断」できることが目的。実装の逐条解説にしない。
- コメント全体で長くても画面2〜3スクロール程度。長くなる場合はファイルごとの説明を中心ファイルだけに絞る。
- 推測を断定で書かない。不明点は「注意点」に「要確認」として残す。
